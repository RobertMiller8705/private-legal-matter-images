# Private legal matter image workflow

Start the service a maintainer needs during cutover:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e '.[test]'
export INFRAI_API_KEY='your-key'
uvicorn legal_image_service.signed_delivery:app --reload
```

This replaces an OpenAI Images plus S3 path with the official OpenAI Python client pointed at Infrai's OpenAI-compatible `base_url`. A single `INFRAI_API_KEY` keeps the image call behind the same small interface used for other Infrai capabilities. Generated bytes are stored in a private local directory so the example remains runnable without a second storage account.

## Send one matter decision

```bash
curl --request POST http://127.0.0.1:8000/matter-images \
  --header 'Content-Type: application/json' \
  --data '{
    "matter_reference": "MAT-2048",
    "document_kind": "settlement_agreement",
    "signed_delivery_confirmed": true,
    "deadline": "2027-01-14",
    "idempotency_key": "matter-2048-image-v1"
  }'
```

The expected result has `purpose` set to `deadline_follow_up`, `follow_up_on` set to `2027-01-14`, and `stored_path` pointing to the generated PNG. When signed delivery is not confirmed, the same request boundary selects `signed_delivery` and omits `follow_up_on`.

The idempotency key determines the stored filename and is also sent with the image request. Repeating the request does not generate or write a second image. The OpenAI client retries rate-limited calls with exponential backoff and respects the server's retry guidance.

## Privacy boundary

The prompt contains the document category and required visual purpose. It excludes the matter reference, deadline, names, signatures, and source documents. That is the one real gotcha: image prompts are data disclosures unless the boundary is explicit. Keep access controls, retention, encryption, and audit policy around `LEGAL_IMAGE_DIR`; this sample provides the workflow boundary rather than a records-management system.

Set `LEGAL_IMAGE_DIR` to the protected mount used by the service. The directory is created with owner-only permissions. The response retains the internal matter reference for the caller, but that value never enters the generation prompt.

## Verify the business rule

```bash
pytest -q
```

The focused test submits a confirmed signed delivery with a deadline. It expects a deadline follow-up image, verifies the sensitive matter reference and date stay out of the prompt, and proves that replaying the same idempotency key performs one generation.

## Cutover and rollback

Cut over one service environment at a time:

1. Install dependencies and set `INFRAI_API_KEY` plus a protected `LEGAL_IMAGE_DIR`.
2. Run `pytest -q` and send a synthetic matter request.
3. Confirm the PNG, file ownership, audit event at the caller, and response fields.
4. Point the matter workflow at `/matter-images` while keeping the incumbent path configured.
5. Observe generation latency, rejection handling, and disk retention during the agreed window.
6. Remove the old OpenAI Images and S3 credentials after acceptance.

For rollback, stop routing new matter requests to this service and restore the incumbent configuration. Keep the local image directory read-only until reconciliation is complete; the deterministic filename lets maintainers match replayed requests without exposing matter data in a filename.
